# Solar PV Design Platform v2.0 Alpha 1 Release Notes

**Release:** v2.0 Alpha 1  
**Date:** 29 August 2026  
**Application:** `2.0-alpha1`  
**Server:** `2.0.0-alpha.1`  
**Project schema:** `2.0`  
**Rule-pack schema:** `2.0.0`  
**Frozen compatibility rule engine:** `1.9.0`

## Purpose

Alpha 1 implements the formal rule-pack contract and compatibility freeze required before adding any new engineering standards content. It is a controlled evolution of the frozen v1.9 Final source tree, not a rebuild.

## Added

- `solar_pv_design_platform_v2.0_rulepacks.js`: formal contract/validator, v1.9 compatibility adapter, deterministic canonicalization, SHA-256 contract fingerprints, safe import/export, constrained overlays, capability-state API, compatibility evaluation, and engineering-rule migration helper.
- `schemas/solar_pv_rule_pack_schema_v2.0.0.json`: machine-validatable JSON Schema Draft 2020-12 contract with explicit units, identity/versioning, compatibility, evidence, capability, lifecycle/claim, and overlay declarations.
- Four committed v1.9 golden compatibility fixtures and their deterministic generator.
- Representative native v2 contract fixture used for schema/import/export testing only; it does not introduce new standards data.
- v2.0 core/server wrappers preserving existing module/repository architecture and the established SQLite filename.
- Section 17 UI additions for formal schema/engineering version/fingerprint/compatibility/capability/review/evidence/overlay state plus formal pack import/export.
- v2.0 project migration/provenance fields and deliverable provenance extensions.
- Dedicated v2 static/rule/server acceptance tests.

## Security and deterministic behavior

- Rejects `__proto__`, `prototype`, and `constructor` recursively on imported packs and project overlays.
- Rejects unknown engineering keys and forbidden/immutable overlay paths.
- Rejects numeric engineering strings rather than silently coercing them.
- Enforces table shape/range/monotonicity for approved v1.9 overlay paths.
- Rejects duplicate `packId@engineeringVersion` registry identities.
- Verifies deterministic import-envelope fingerprints.
- Preserves the historical v1.9 `rule-xxxxxxxx` fingerprint namespace and introduces a separate `rulepack-v2-sha256-...` namespace for formal contract artifacts.

## Compatibility preserved

- All four frozen v1.9 built-in rule packs are exposed through compatibility contracts and compared against committed golden results.
- Frozen v1.9 geometry/layout/rule/electrical/energy/repository/Worker modules remain unchanged.
- Existing string/MPPT, detailed electrical, energy/finance, project/revision, repository, Worker/fallback, and deliverable source paths are retained.
- v1.7/v1.8/v1.9 project-schema compatibility remains in the v2 project migration path; unknown schemas are rejected.
- v1.9 rule fingerprints/provenance remain traceable through migration.
- `.solar_pv_data/solar_pv_v17_alpha6.sqlite3` remains the default repository database; DB schema remains version 1.

## Engineering claims deliberately not added

No new IEC, NEC, utility, fire, structural, earthing, fault-current, breaking-capacity, disconnection-time, protection-coordination, SPD-coordination, standards ampacity, or jurisdiction-specific tables were added. The formal capability layer reports unsupported/not-validated states for deeper domains instead of fabricating results.

The inherited preliminary packs remain software-tested compatibility artifacts, not independently reviewed construction-ready compliance packs.

## Browser status

Full browser workflow UAT is **not claimed** from this build environment. Chromium 144 is present, but administrator policy blocks local HTTP and `file:` navigation with `net::ERR_BLOCKED_BY_ADMINISTRATOR` before the application page can be requested. A direct real-Chromium JavaScript runtime smoke of the v1.9 rule engine + v2 contract module passed; this is recorded separately and does not replace UI UAT.

## Next gated phase

Alpha 2: add a rule evidence ledger so every reportable engineering rule decision maps to source/provenance, units, applicability, assumptions, implementation status, validation status, and deterministic regression-test IDs. Do not add deeper engineering formulas before that evidence chain is complete.
