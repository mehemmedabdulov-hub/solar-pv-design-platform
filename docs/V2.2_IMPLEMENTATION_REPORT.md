# SOLAR v2.2 Implementation Report

Date: 2026-09-03  
Release: **SOLAR v2.2 — Experience + Drawings**  
Protected calculation/runtime baseline: **v2.1**  
Project schema: **2.0**  
Rule-pack schema: **2.0.0**

## 1. Before / after workflow

**Before (v2.1):** the browser shell exposed 17 major card sections through a long page. The user repeatedly moved between site geometry, equipment/layout, manual panel editing, electrical details and deliverables. Panel editing was primarily one-panel-at-a-time. The SLD was a deterministic but web/block-style SVG overview.

**After (v2.2):** Simple Mode presents five primary stages with a persistent stepper and sticky readiness/next-action area:

1. Project & Location
2. Site Geometry
3. PV System
4. Electrical + SLD
5. Review & Export

Engineer Mode exposes the retained detailed engineering cards/controls inside the same staged shell. Values are not reset when modes change.

## 2. Source-of-truth boundary

No v2.2 UI module contains a replacement layout/electrical/energy/finance/rule-pack formula set. The existing v2.1 calculation modules remain the numerical source. The SLD drawing model consumes the current deterministic `buildElectricalObjectModel()` result. Electrical ratings, cable/protection rows, string/MPPT assignments and source fingerprints are data-bound references; drawing coordinates and annotations are separate visual state.

The compatibility markers intentionally remain:

- calculation/runtime application version `2.1`;
- project schema `2.0`;
- rule-pack schema `2.0.0`;
- existing v1.9 compatibility runtime modules and frozen hashes.

The new UI advertises an additional v2.2 **experience/drawing** version rather than changing those protected contracts.

## 3. Readiness / dependency model

`workflow.js` exposes a presentation-level dependency chain:

`Project → Site → Layout → Electrical → SLD → Review/Exports`

States shown to the user are derived from existing result/readiness objects plus explicit downstream invalidation. Accepted panel geometry edits mark **Electrical** and **SLD** `Stale`. The old SLD is deliberately held, labelled stale and blocked from drawing export until the electrical result/SLD is refreshed. A drawing is current only when its `sourceFingerprint` matches the current electrical object model.

The sticky action changes with state (Continue, Generate Solar Design, Refresh Electrical, Refresh SLD, Generate Engineering Pack) and does not duplicate calculation formulas.

## 4. Panel editor implementation

`panel-editor.js` moves the existing map into a map-centered array-editing workspace and adds:

- Select, Add Module, Add Row, Box Select, Measure and Obstacle tools;
- Ctrl/Cmd/Shift multi-selection;
- selection toolbar for Move, Rotate, Align, Distribute, Lock/Unlock and Delete;
- selection inspector with exact group rotation, surface, IDs/rows/string state and locks;
- validated group drag with green/red candidate preview;
- row placement that accepts only valid candidate positions;
- align/distribute operations using the configured module gap;
- selected-surface regenerate plus confirmed reset-to-auto-layout;
- a bounded command stack for undo/redo; and
- keyboard shortcuts disabled while focus is inside INPUT/SELECT/TEXTAREA.

### Group validation safety

The existing `validateManualPanelPolygon()` body and exact buildable-area logic remain authoritative. Its optional ignored-panel parameter was extended to accept a selected `Set`/Array so group candidates can be checked against all non-selected panels. `panel-editor.js` calls this validator for **every candidate module**. Candidate-to-candidate checks reuse the existing `polygonsInteriorOverlap()`, `polygonMinimumDistance()` and configured gap value before a transform can commit.

Normal invalid edits use the ghost preview/inline status/toast system rather than a blocking browser alert.

## 5. SLD drawing model

`sld-drawing-model.js` creates a normalized drawing document with:

- `sourceFingerprint`, project/revision identity and drawing metadata;
- design-bound nodes with stable `designRef`, `designType`, tag and electrical-data references;
- design-bound circuit edges with cable/current/voltage-drop/protection references where the v2.1 result supplies them;
- separate X/Y and route state that does not alter source design values;
- separate `drawingFingerprint` for visual state;
- drawing-only annotations explicitly marked `bound:false`;
- Electrical, Labels, Notes, Title Block and Optional Details layers;
- Compact and Detailed modes; and
- IEC-style / ANSI-style presentation profiles.

Manual node positions/tags/notes and annotation objects are preserved across regeneration while their referenced design objects survive. New design objects are auto-placed. A meter or other optional component is not generated unless the source model actually contains supporting data.

## 6. CAD-style SLD and editor

The E-401 renderer now uses a structured A3 landscape engineering sheet rather than decorative web cards. It includes:

- PV/DC, inverter/protection, AC distribution and grid zones;
- vector electrical symbols and stable tags;
- orthogonal circuit paths;
- conductor configuration/size/material/length/current/voltage-drop labels where known;
- protection text from the source circuit rows;
- generated legend and system specifications;
- revision/general-note blocks;
- project/site, schema, calculation-engine, rule-pack and source-fingerprint metadata; and
- a visible `PRELIMINARY · NOT FOR CONSTRUCTION` status.

The generated SLD is read-only by default. **Edit Drawing** adds CAD-like visual operations: multi-select/drag, grid/snap, pan/zoom, fit, align/distribute, drawing-only circuit reroute/reset, layer visibility, annotation note/label/arrow/cloud creation, annotation copy/paste, undo/redo and reset-to-auto-layout.

Calculated ratings are read-only in the editor. Design-bound components cannot be deleted there; users are directed back to the upstream electrical design. Drawing annotations can be removed freely.

## 7. SLD preflight and staleness protection

Preflight checks:

- module/inverter identity;
- string inverter/MPPT assignment;
- cable/protection values when applicable;
- connector references and generated-node connectivity;
- duplicate tags;
- off-sheet generated objects;
- unsupported component types; and
- stale electrical source fingerprint.

Missing data is shown as `NOT SPECIFIED`; it is not filled with fabricated code values. Drawing export requires current electrical/SLD fingerprints. Preliminary status is never promoted to permit/construction-ready by the UI.

| Native DWG | **Not implemented** | Intentionally not faked or produced by renaming DXF. |

The Engineering Pack manifest records both the electrical `sourceFingerprint` and project `stateFingerprint` when available. A stale SLD is replaced with a freshly generated drawing bound to the pack's current electrical source rather than silently mixing fingerprints.

Because that policy prevents the application from loading in Chromium, full interactive desktop/tablet/mobile browser smoke execution could not be truthfully claimed here. `docs/UI_SMOKE_CHECKLIST_V2.2.md` contains the exact browser checks to run in a normal Codespace/browser. Automated runtime, server/static, model and export checks above all passed.

These are not presented as completed work:

- Add optional user-supplied datasheet appendices to the Engineering Pack only when licensing/source availability is explicit.
