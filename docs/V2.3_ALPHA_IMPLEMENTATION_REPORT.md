## A1 - Explicit location lifecycle and geometry lock

**Before:** map clicks could call the coordinate setter after geometry existed, allowing project coordinates to diverge from location-bound geometry/shading state.

**Implemented:** `v23-alpha-controller.js` supplies `Unconfirmed -> Confirmed -> Locked-by-geometry`. Map clicks only act while explicit Set Location mode is active. Coordinate entry and GPS use the same guarded request path. Existing site surfaces or shading-origin data trigger a non-blocking Relocate Project decision. Cancel restores canonical inputs without applying coordinates. Confirmed destructive relocation clears location-bound site/shading state before the new coordinate is applied, explicitly invalidates resource and derived domains, and does not create/replace a formal revision. Working snapshots persist lifecycle state without a schema bump.

**Commit:** `d5a323a87e2c674992930e49fc980cc02b90625e`

## A2 - Installation-type migration guard

**Before:** Rooftop/Ground/Carport radio changes over existing geometry immediately rewrote `surfaceKind`, default-looking names and sub-array IDs.

**Implemented:** committed installation type is separate from the tentative radio request. With no geometry the compatible v2.2 behavior remains immediate. With geometry, the selection is restored to the committed value while a non-blocking migration decision is pending. Cancel does not commit the request. Confirmed migration preserves polygon coordinates, changes only type-specific/default metadata, renames only exact default-pattern names/IDs, preserves customized names/IDs, invalidates layout/downstream state once, refreshes UI state and schedules working-draft persistence only after commitment.

**Commit:** `05aa1dcf1b5c55c898deecc1d6914f5ed28c1ad3`

## A3 - Deliverable generation decoupling

**Before:** `updateDesignResults()` and ordinary metadata/rule-change paths could rebuild the electrical object model/BOM/SLD/report during generic foreground refresh.

**Implemented:** `updateDesignResults()` no longer calls `updateEngineeringDeliverables()`. Normal technical results still update, then `markDeliverablesStale()` marks the last successful deliverable source stale without rebuilding it. Project/customer metadata edits mark deliverables stale without unnecessarily rerunning engineering calculations. Explicit SLD/electrical refresh and explicit export-on-demand paths remain generation boundaries. Stale export cannot be presented as current. Instrumentation records generic refreshes, stale marks, explicit generations and electrical-object-model builds so the no-implicit-build contract is testable.

**Commit:** `1f63c1e883b77b14bc6494a514c86404d9d6b942`

## A4 - Release wiring and packaging

The visible release label identifies **SOLAR v2.3 Alpha orchestration** while preserving the inherited v2.2 experience/drawing compatibility marker. The calculation engine remains 2.1; project schema remains 2.0; rule-pack schema remains 2.0.0. `tests/run_v23_alpha_verification.sh` runs the complete v2.2 suite first and then all Alpha tests. Protected-file hashing covers the selected v2.1 engine/schema files plus retained v1.9 compatibility sources, while a server test verifies the new Alpha controller and inherited UI assets are served by the existing v2.1 server.

Legacy blocking `alert()` debt in `index.html` decreased from **33** in the supplied v2.2 baseline to **24**. No blocking `alert()` remains in the Alpha-touched location, installation migration or deliverable/export paths. Unrelated alerts are deliberately retained as documented debt rather than being rewritten outside Alpha scope.

## Protected baseline result

The protected-file test reports **PASS (12 protected engine/schema files unchanged)**. The inherited v2.2 verification additionally rechecks the retained frozen v1.9 hash inventory. No expected numerical output was changed to make the suite pass.

## Known limitations and carry-forward debt

- Browser/runtime interaction is blocked by administrator browser policy here. Static/unit/server tests do not replace Gate 4.
- 24 unrelated legacy `alert()` calls remain outside the Alpha-touched critical paths.
- Full ProjectState/DerivedState normalization is intentionally not part of Alpha.
- SLD/BOM/report generation remains synchronous at explicit generation boundaries; workerization is reserved for the later phase that specifies it.
- Beta, Gamma and Delta are not implemented or inferred in this package.

## Release decision

**NOT READY FOR v2.3 BETA.** The implementation and all available non-browser verification are green, but the Alpha playbook requires real runtime/interaction evidence. Start Beta only after the blocked A1-A4 browser checks are executed in a capable environment and recorded as PASS.
