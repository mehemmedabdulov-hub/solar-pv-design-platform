15. Advanced 3D / Point-Cloud Shading

Version 1.7 retained 3D/shading engine. Shading data uses an explicit local ENU coordinate reference tied to the project origin, imported data carries provenance and unit metadata, geometric shading can sample multiple deterministic points per sub-array, and obstruction lookups use a spatial index. Large text imports are bounded and reported rather than silently exhausting the browser. Binary LAS/LAZ, GeoTIFF terrain, full mesh intersection, and bankable module-level ray tracing remain future architecture work.
Higher sampling resolves local obstruction differences without changing the deterministic energy time step.
All imported geometry is converted to canonical local metres before storage.
Local ENU: X/east, Y/north, Z/up in metres relative to the stored project origin.
Text import limit: 30 MiB / 500,000 usable points; points more than 5 km from the project origin are ignored.
No point-cloud or mesh import provenance is stored for this project.

Deterministic Execution Runtime

Worker runtime is idle. The external alpha6 worker module will start on the first supported heavy task; deterministic main-thread fallback remains available.
The first extracted workload remains point-cloud grid summarization; alpha6 adds a separate persistent server/database boundary. The worker receives a packed Float64 coordinate buffer and returns deterministic grid-cell records only; project state, Leaflet layers, DOM objects, and engineering results remain on the application thread. Worker failure never silently changes the algorithm: the same summarization core is executed on the main thread and the fallback is reported.
